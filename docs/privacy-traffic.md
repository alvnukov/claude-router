# Подключение privacy к трафику

Исходная ветка реализации: `codex/privacy-ui`, интегрирована с main `84bfdf6`
и установленным исправлением UI `4689546` (сроки и число сбросов лимитов).
Рабочий сервис обновлён до `3545702` 2026-09-27 (исправление штатного `beta=true`
после установки `1c059a4`). При проверке обновления privacy рабочего трафика выключен;
пользовательский профиль детекта сохранён без изменений. Проверка установки — ниже.

**Актуальный контракт рабочего трафика:** маскируется только поддерживаемое
содержимое: текст сообщений, строковые значения аргументов инструментов и
описания схем. Служебные поля, metadata, thinking/signatures, неизвестные блоки,
вложения, идентификаторы, ключи объектов и нестроковые значения сохраняются.
Их наличие не блокирует запрос и не отключает маскирование поддерживаемого текста.
Исключение — блоки thinking без подписи (рассуждения Codex): перед Anthropic они
удаляются, и при незавершённом ходе thinking выключается, как описано в
`docs/features.md`, раздел 2.
Это не гарантия обезличивания всего запроса: данные в непрозрачных полях остаются
видимыми провайдеру. При переводе в OpenAI/Codex действует обычное отображение
полей переводчиком; privacy не добавляет ограничений на client controls.

Подсчёт токенов проходит через профиль выбранной модели. Прямой Anthropic
получает подготовленный запрос на count_tokens; локальные маршруты возвращают
существующую оценку размера без генерации и без изменения привязки сессии.
Исторические отчёты о прежних отказах ниже не описывают текущий контракт.

## Дополнительный аудит совместимости

- Повторные `Anthropic-Beta` сохраняются согласно [контракту API](https://platform.claude.com/docs/en/api/beta-headers#multiple-beta-features).
- Ответы прямого upstream 400/401/403/404/413/429/5xx сохраняют статус: клиент может отличать ошибку запроса, авторизацию и ограничение частоты. Тело ошибки заменяется безопасным сообщением; сырые headers не копируются. [Коды ошибок Anthropic](https://platform.claude.com/docs/en/api/errors).
- Потоковый парсер принимает комментарии, служебные поля, многострочные data, LF/CRLF/CR и BOM по [стандарту SSE](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream). Проверены разрывы сетевых chunks, сохранение непрозрачных кадров и восстановление псевдонимов. Ошибочный JSON и незавершённый поток по-прежнему отклоняются.
- `propertyNames` сохраняется как структурное ограничение схемы, чтобы имена полей не расходились с `properties` и `required`.
- Локальный count_tokens учитывает действующую привязку сессии к модели, не создавая и не продлевая её. Поэтому профиль count совпадает с выбранной моделью.

После исправлений прошли полный `go test -p 1 ./...`, целевые проверки с `-race`, `go vet ./...` и установленный Claude Code через локальный тестовый upstream в detect/mask. Ревью дополнительно закрыло ложный terminal при BOM в середине потока и отправку Retry-After после истечения deadline.

## Контракт

При существующем включённом privacy-profiles.json каждый запрос получает неизменяемый снимок политики. Перед каждой попыткой отправки выбирается профиль фактической модели (model > pool > provider > default). Ошибка правил, словаря, разбора или восстановления закрывает запрос; исходное тело не используется как запасной вариант. Выключенный профиль / отсутствие назначения — явный обход, видимый в счётчиках. Невалидный файл блокирует трафик даже если прошлый снимок был выключен. Удаление файла после включения не отключает защиту: сохраняется приватный маркер privacy-required.

Поддерживаются POST /v1/messages и /v1/messages/count_tokens, Anthropic, перевод OpenAI Chat и Codex Responses. Неизвестные адреса при включённой защите запрещены. Управление локальными профилями и healthz остаётся локальным. Фоновые проверки доступности не содержат пользовательских запросов.

Исходное Anthropic-тело маскируется до перевода протокола, отдельно для каждой попытки. Словари разделены по ID профиля и SHA256 правил; изменение правил не меняет уже выполняющийся запрос. metadata сохраняется, а session_id также используется локально. Этот роутер рассчитан на доверенного локального клиента; session_id не является авторизацией изолированных пользователей.

Неподдерживаемые поля остаются без изменений. Подписанный thinking в истории
не требует ранее созданного словаря. Tool/schema identifiers не переименовываются.
Рабочий трафик сохраняет вложения независимо от лабораторного sources: withhold.
При восстановлении заменяются только точные псевдонимы текущего снимка;
неизвестные, изменённые или чужие псевдонимы остаются без изменений и не дают
доступа к чужому словарю. Ошибки JSON, лимитов, хранилища и криптографии
по-прежнему возвращают ошибку, без отправки исходного тела вместо маскированного.

Прямой маршрут сохраняет протокольные заголовки `Anthropic-*`, включая заголовки новых SDK, без проверки их содержимого фильтром privacy; пользовательский User-Agent, cookies и forwarding headers не передаются в защищённую попытку. Для обоих Messages endpoints разрешены пустая query и единственный параметр `beta=true`, включая эквивалентное URL-кодирование и завершающий `&`. При прямой отправке Anthropic этот протокольный флаг сохраняется; при переводе в другой протокол не переносится. Дополнительные и повторные параметры, неверное URL-кодирование и другие значения beta отклоняются до отправки. Учётные данные самого провайдера необходимы для авторизации и не маскируются. Переходы HTTP запрещены. Исходные тела ошибок upstream не попадают в журнал/клиент. Прямой Anthropic сохраняет HTTP-статус ошибки и стандартный безопасный error.type; Retry-After для 429/503/529 передаётся только после разбора числа или HTTP-даты с пределом 24 часа.

Включённый режим не записывает тела, заголовки, session_id и восстановленные значения в историю запросов. Лаборатория по-прежнему изолирована. Наблюдение содержит только счётчики и состояние конфигурации.

## Только детектировать

Профиль может иметь `"mode":"detect"`; `"mode":"mask"` и отсутствие поля
означают обычное маскирование. Неизвестный режим делает конфигурацию невалидной.
Назначения модели/пулу/провайдеру выбирают режим вместе с правилами, без смешения
профилей. Уже принятый запрос сохраняет режим своего снимка.

Детект предназначен **только для заведомо некритичных данных**: исходное тело
запроса отправляется провайдеру без маскирования, ответ не демаскируется.
При переводе Anthropic → OpenAI/Codex сохраняется содержимое, а структура меняется
по обычным правилам переводчика. Счётчики `traffic.detected` и `traffic.findings`
отделены от `protected`, `bypassed` и `restored`. В историю тела не записываются;
session dictionaries, aliases и native Codex replay не создаются и не читаются.
Маркер обязательного файла конфигурации сохраняется и для режима детекта.

`Engine.Detect` применяет те же правила к поддержанным текстовым полям,
аргументам инструментов и описаниям схем: словарь, шаблоны, типизированные поля,
allow/allow_paths и переключатели. Поддержанные кодировки используют только
секреты текущего запроса. В рабочем трафике вложения и непрозрачный thinking не анализируются и не входят
в счётчики. Лабораторный детект отдельно считает вложения для sources: withhold.
Метаданные/протокольные идентификаторы не входят в счётчики текстового детектора.
Ноль находок не означает, что данные безопасны или все сущности распознаны.

Когда все включённые профили используют детект, транспорт работает как наблюдатель:
ответы Anthropic передаются сразу, без накопления и проверки формата; статусы,
ошибки провайдера и новые SSE-события сохраняются. Локальные провайдеры используют
обычный переводчик и потоковую передачу. Включённые профили маскирования сохраняют
защищённый транспорт, в том числе при смене провайдера в пуле.

Ошибка анализа или превышение бюджета детектора не блокирует запрос и учитывается
в `traffic.detection_errors`; успешный анализ — в `traffic.detected`. Сам анализ
ограничен 32 MiB, однако это не лимит передачи запроса. Транспорт наблюдения использует
обычное чтение тела для маршрутизации; 512 MiB — мягкий ориентир GC, не предел RSS.
Текст и реальные значения в наблюдение и историю не сохраняются; ограничения
native Codex replay остаются, чтобы не создавать незащищённые записи диалога.

В лаборатории `operation: detect` работает и для профиля, и для одного фильтра.
Возвращается исходный текст и `detected`; `id` пуст, `roundtrip` false, временный
словарь отсутствует. UI убирает восстановление и явно показывает отсутствие
защиты. Статистика лаборатории `detects`/`detected` отдельна от рабочего трафика.

## Атомарность и ограничения

При маскировании JSON и SSE целиком накапливаются в памяти до успешной проверки. Клиент получает SSE после завершения генерации. Это сознательная цена за запрет частичного исполнения tool call. Предел запроса 32 MiB, ответа 16 MiB. Фиксированного ограничения числа одновременных защищённых запросов нет. При запуске сервера Go получает мягкий ориентир памяти 512 MiB, если `GOMEMLIMIT` не задан в окружении процесса до запуска. Это настройка сборщика мусора, а не жёсткий предел памяти процесса: при большом объёме живых данных расход может превышать ориентир. Она не возвращает клиентам 503 при параллельной работе. До завершения потока обязательны message_stop и корректные события. Неизвестные/изменённые псевдонимы сохраняются без эвристического исправления; роутер сам не повторяет генерацию.

Секреты запроса живут до завершения ответа. Сессионные словари остаются локальными в privacy-runtime/<profile>-<rules-hash>/; права каталога/файлов задаёт существующее хранилище. Нулевая остаточность в памяти Go не гарантируется. Повторяющиеся сессии сохраняют псевдонимы; производительность 400k токенов и 2000 RPS не обещается этим этапом.

Фактический путь словаря — `privacy-runtime/<profile>-<rules-hash>/privacy/sessions/<session-id>.jsonl`.
Он содержит соответствия и ключ преобразования, без шифрования на диске; права
каталогов `0700`, файлов `0600`. Распознанные секреты сохраняются только как
HMAC-отпечатки, сами значения — в памяти запроса. Без корректного `session_id`
словарь ограничен запросом и не сохраняется. Лаборатория хранит словарь в памяти
5 минут, до очистки либо перезапуска; детект словарь не создаёт.

`retain_days` по умолчанию равен 30 и относится к неактивности сессии, но очистка
запускается только при инициализации соответствующего engine или явном `Prune`.
Периодической очистки в runtime нет. Изменение правил выбирает новый каталог;
автоматическая уборка каталогов прежних версий не реализована. Поэтому срок
удаления в 30 дней не гарантирован. Обычный перезапуск сохраняет словарь при
неизменных профиле, правилах и ID сессии; незавершённый запрос после аварийного
перезапуска не восстанавливается.

## Проверки

Синтетические HTTP-upstream: обычный ответ, SSE с разрезанным псевдонимом, ошибочные tool arguments, failover с разными профилями, count_tokens, ограничения адресов/заголовков, сохранение metadata, отсутствие чувствительных данных в истории и ошибках. Отдельно: изменение/удаление/порча конфигурации, изоляция словарей, отмена, лимиты. Финальный отчёт добавляется после проверок.

## Независимое ревью и исправления

Два независимых прохода (спецификация/риски и стандарты/ресурсы) нашли реальные
дефекты. Каждый закрыт воспроизводящим регрессионным тестом:

| Риск | Проверка |
|---|---|
| Ложное `type=image/document` в схеме или настройках | `TestTrafficReviewFalseSourcesAndNumericIdentifiers` |
| Числовая форма словарного идентификатора | тот же тест; необрабатываемые скаляры отклоняются при совпадении |
| Секреты в Beta/Version и фактическом ID модели | `TestPrivacyTrafficReviewProtocolHeaderLeak`, `TestPrivacyTrafficReviewActualModelAndHeaderSecrets` |
| Неизвестный псевдоним в SSE control metadata, неверный тип delta, лишнее поле | `TestTrafficReviewSSEControlsAndBlockTypes` |
| Короткий ответ разворачивается в огромный оригинал | `TestTrafficReviewExpansionBoundBeforeAllocation`; 11.7 KiB входа, 300 копий секрета 64 KiB, отказ до массовых выделений |
| Тело ошибки попадает в health/log | `TestPrivacyTrafficReviewLateErrorDiagnosticsAndTrailingJSON`, `TestPrivacyTrafficReviewStreamDiagnostics` |
| Trailing JSON и ложный EOF на лимите ответа | `TestPrivacyTrafficReviewLateErrorDiagnosticsAndTrailingJSON`, `TestPrivacyTrafficReviewOversizeWhitespace` |

Бюджет восстановления учитывает JSON-экранирование до построения результата,
в том числе вложенный JSON в SSE. Уменьшающие замены не дают дополнительного
бюджета: около лимита возможен консервативный отказ. Общий SSE-буфер ограничен.
При ошибке ни префикс текста, ни tool call клиенту не выдаётся.

Дополнительно исправлены прежние пробелы детектора: assignment-пароль после
пробела в строке и пароль короче восьми символов. Переводчики протоколов больше
не заменяют повреждённые tool arguments пустым объектом, не пропускают сломанные
JSON-события и не принимают повторяющиеся ключи.

## Ограничения для продолжения

- Подписанный thinking в истории и включённый Anthropic thinking отклоняются;
  provenance ещё не реализован. Результат нельзя считать полным агентным шлюзом.
- Codex требует полного tool call в истории клиента. Восстановление пропущенных
  вызовов из старой незамаскированной request history в защищённом режиме запрещено.
  После интеграции native Responses из main отключены также импорт/сохранение
  native replay, session/cache affinity и автоматические sampling continuation
  при глобально включённом privacy. Для них пока нет provenance, привязанного
  к профилю и версии правил. Обычный следующий запрос клиента поддерживается.
  При глобально выключенном privacy штатный маршрут Codex сохраняется; текст
  ошибок и небезопасные заголовки ответа нормализуются, а не возвращаются сырыми.
- Защищённый прямой Anthropic не сохраняет upstream response headers; в этом
  режиме прежние показатели квот от ответов не обновляются. Собственная privacy
  статистика доступна. Авторизационные заголовки провайдера остаются необходимым
  исключением из маскирования; произвольные заголовки клиента удаляются.
- Снимок Engine переиспользуется, но конфигурация читается и валидируется на каждом
  запросе; кэш разбора и повторяющегося контекста, целевые RPS и замеры 400k токенов
  остаются отдельным этапом. Словари профилей/версий изолированы; старые namespace
  не удаляются автоматически при смене правил.
- NER, неизвестные личности, произвольные разбиения/стеганография, допустимость
  команд и прямой доступ инструментов в сеть остаются вне доказанного покрытия.
  Для выполнения команд нужны отдельные проверки доступа и исполнения.

Решения при выполнении: оставлено буферизированное SSE ради атомарности; отсутствие
provenance закрывается отказом, а не пропуском. Цена этих решений — задержка ответа, ограничение поддержанных
сценариев и отдельный шаг интеграции/установки. Неоценённые ревьюерами throughput,
production deployment, UI и полный regression suite не выдаются за результат
их независимого аудита; UI и тесты проверяет исполнитель.

## Интеграция с main перед установкой

Конфликты с `84bfdf6` разрешены в worktree: сохранены native Responses и новые
показатели расхода/кэша UI. Преобразование изображений tool output и обрезка
контекста выполняются после маскирования. Новые Codex SSE проверяются до
декодирования: duplicate keys и невалидный UTF-8 отклоняются, тело ограничено
16 MiB. Callback `Options.ValidateEvent` оставляет протокол независимым от privacy.

Регрессионные тесты `TestPrivacyCodexDoesNotImportOrPersistOpaqueState` и
`TestPrivacyCodexRejectsContinuationAndMalformedEvents` сначала воспроизвели
импорт/сохранение старого native state, второй сетевой запрос continuation,
принятие duplicate keys и исправление UTF-8. После исправлений все эти сценарии
закрываются отказом до выдачи ответа либо проходят без обращения к native store.
Старая успешная Codex fixture получила обязательный `response.id`, как требует
новый протокол main; проверка маскирования/восстановления не ослаблялась.

Дополнительное независимое ревью нашло приём раннего tool call при изменённом
