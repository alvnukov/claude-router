# Передача разработки маскирования

Этот комплект позволяет продолжить разработку в обычном clone репозитория без
доступа к внутренним заметкам, рабочим каталогам или прежним участникам проекта.
Срез исходного кода: `1f086271dd8e5cb6dd722c63f3a2de3eb869c9b0`.
Ветка передачи: `feature/privacy-mask-all`. Дата сверки: 2026-10-01.

**Работа не завершена. Ветка не является готовой защитой всего трафика.**
Документы описывают целевую систему; фактическую реализацию и пробелы фиксирует
[STATUS.md](STATUS.md). В рамках подготовки передачи продуктовый код не менялся.

## Порядок чтения

1. [STATUS.md](STATUS.md): что действительно есть в коде, что осталось, где WIP.
2. [SPEC.md](SPEC.md): целевые требования, границы защиты и критерии приёмки.
3. [NETWORK.md](NETWORK.md): контракт сетевых перестановок, неподвижных точек,
   форм адресов и восстановления.
4. [PLAN.md](PLAN.md): порядок реализации, задачи, отрицательные тесты и мутации.
5. [ROUTING.md](ROUTING.md): зависимость от маршрута классификатора и контракты
   отправки/восстановления для следующих этапов.
6. [VERIFICATION.md](VERIFICATION.md): свежие результаты и команды для продолжения.
7. [OPEN-QUESTIONS.md](OPEN-QUESTIONS.md): непринятая развилка для Anthropic и
   вопросы, которые нельзя молча превращать в новые требования.

SPEC и NETWORK задают целевое поведение; PLAN задаёт порядок достижения;
STATUS и VERIFICATION описывают доказанное состояние конкретного среза.
Предложение `inspect-only` для Anthropic остаётся непринятым и не отменяет SPEC.
Старые общие документы в `docs/` описывают прежние этапы и не заменяют этот
комплект. Если код, план и требование расходятся, сначала зафиксируйте расхождение,
а затем уточните техническое решение с сопровождающим проекта.

## Начало работы

Получите ветку `feature/privacy-mask-all` из этого репозитория и создайте свою
ветку продолжения от её HEAD. Используйте Go из `go.mod` и изучите существующие
`CLAUDE.md`/`AGENTS.md`, если работаете агентом. Внешние персональные файлы правил
не являются зависимостью этого комплекта. Команды ниже выполняются из корня repo.

```sh
go build ./...
go test -count=1 ./internal/privacy/cryptopan ./internal/platform
```

В свежем clone тестовая заготовка находится только в `artifacts/` с расширением
`.pending`; Go её не компилирует. В исходной рабочей копии существует также
неотслеживаемый `internal/privacy/keys_test.go`, который пока не компилируется.
Это намеренно сохранённый незавершённый тест, а не зелёная реализация задачи 1.3.

## Первый рабочий цикл

1. Зафиксировать baseline свежего clone. Не переносить старые runtime-файлы.
2. Проверить и применить небольшое сетевое продолжение из
   [artifacts/network-followup.patch](artifacts/network-followup.patch).
   Оно содержит переименование метода mapper из следующего локального коммита
   `de1b8fa` и закрывает отставание среза от сетевой ветки.
3. Разобрать [artifacts/windows-session-append.patch](artifacts/windows-session-append.patch):
   снятие `O_APPEND`, `Truncate(validBytes)`, `Seek(validBytes)`, запись под тем же
   межпроцессным замком. Проверить тесты и мутации из PLAN, затем реальный Windows CI.
4. Продолжить задачу 1.3, используя сохранённую заготовку
   [artifacts/keys_test.go.pending](artifacts/keys_test.go.pending). Это ожидаемый RED:
   интерфейсы внедрения keyStore, счётчики и runtime-причины ещё отсутствуют.
5. Закончить этап 1 и его приёмку; затем разработать детали этапа 1б и идти по PLAN.

Пример проверки патчей без применения:

```sh
git apply --check docs/handoff/privacy-masking/artifacts/network-followup.patch
git apply --check docs/handoff/privacy-masking/artifacts/windows-session-append.patch
```

Оба патча проверены на применение к срезу `1f08627`, но их продуктовые изменения
не включены в эту ветку. После рибейза повторно проверьте контекст и тесты.
Патч Windows получен из незакоммиченного WIP, не имеет подтверждённого ревью или
живого Windows-прогона. Применение патча не является доказательством исправления.

Чтобы начать тест задачи 1.3 после завершения Windows-шага:

```sh
cp docs/handoff/privacy-masking/artifacts/keys_test.go.pending internal/privacy/keys_test.go
go test -count=1 -run '^TestSessionKeyOffDisk$' ./internal/privacy
```

Тест должен сначала обнаружить недостающую реализацию. Сохраните его требования;
не ослабляйте утверждения ради зелёного результата. В заготовке только синтетика:
фиксированный ключ `00..1f`, тестовый пользователь/хост и примерный домен.

## Что передано и что не передано

- Код и история разработки маскирования находятся в этой же ветке.
- Требования и план перенесены по смыслу с учётом принятых уточнений; внутренние
  имена, домашние пути, переписка и организационные разрешения удалены.
- WIP теста сохранён побайтово; Windows WIP и сетевое продолжение сохранены патчами.
- Производственные данные, ключи, runtime-файлы, учётные записи и конфигурации
  работающего сервиса не включены.
- Новая реализация классификатора из отдельной ветки не входит в срез. Её
  необходимый контракт изложен в ROUTING; не рассчитывайте на доступ к локальным
  веткам или сообщениям прежней команды.
- Ветка отстаёт от текущего `main`; стратегия интеграции требует отдельного ревью.
  Не заменяйте срез маскирования новым `main`, теряя незавершённую работу.

Разрабатывайте и проверяйте на синтетике и временных каталогах. Включение маски
по умолчанию относится к поздней приёмке; запуск/выкат работающего сервиса этим
комплектом не производится.
