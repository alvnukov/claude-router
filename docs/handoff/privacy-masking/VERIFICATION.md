только эту папку; патчи и `.pending` являются материалом для продолжения, а не

## Обезличивание

Новая папка проверяется отдельно от существующей истории repo. В ней нет
личных домашних путей, имён прежних участников, внутренних сессий, закрытых
карточек/журналов или переписки. Технические требования изложены самостоятельно,
с относительными ссылками на документы этого комплекта. `/home/testlogin`,
`test-host.local`, `admin@romashka.example` и фиксированный ключ в `.pending`
являются синтетическими тестовыми данными.

Сканирование новой папки `gitleaks dir` не обнаружило секретов. Дополнительное
сканирование 24 прежних кодовых коммитов `origin/main..1f08627` нашло одну строку
`generic-api-key`: сохранённый синтетический ключ старой v1-сессии в
`internal/privacy/testdata/session_v1/v1fixture.jsonl`, коммит `ef664af`.
Фикстура воспроизводит миграцию/разрыв обратной совместимости PRF, используется
`session_v1_test.go` и содержит тестовые сетевые значения. Это не credential
провайдера; результат сканера не скрывался, тестовая фикстура не изменялась.
Это проверка указанного диапазона, а не обещание аудита всей истории проекта.

## Команды дальнейшей проверки

После внедрения API и принятия патчей выполнить из корня своего checkout:

```sh
go test -count=1 -run '^TestMapUnique$' ./internal/privacy
go test -count=1 -run '^TestSessionKeyOffDisk$|^TestSubkeyHKDF$' ./internal/privacy
go test -count=1 -run '^TestPairStore$|^TestCleanLegacy.*$|^TestRetention$' ./internal/privacy
go vet ./...
go test -count=1 ./...
GOOS=linux go build ./...
```

`TestSubkeyHKDF` и `TestRetention` должны сначала появиться по PLAN. Go допускает
успешный запуск с нулём подходящих тестов: отдельно проверяйте наличие и исполнение
всех требуемых имён. Тесты из будущих этапов не считать пройденными из-за пустого
`-run`. Каждый этап дополнительно имеет собственные интеграционные ряды и мутации.

Проверки OS store с `ROUTER_OS_SECRET_TEST=1` выполнять только в подготовленной
тестовой среде с временным Keychain или уникальной Windows-целью и очисткой.
На Windows нужен реальный logon session с доступным credential vault. Ошибка 1312
должна именоваться и закрывать отправку; не заменять её новым ключом, SKIP или
зелёной cross-сборкой. CI со SKIP не закрывает соответствующий критерий.

Перед включением на стенде завершить условия [PLAN.md](PLAN.md#ворота-включения-и-завершения)
и разрешить противоречия из [OPEN-QUESTIONS.md](OPEN-QUESTIONS.md). Отдельно измерить
кэш, SSE, tool-use и классификатор на реальных моделях с синтетическими действиями.
