## Windows WIP

Старый код открывает файл `O_WRONLY|O_APPEND`, затем вызывает `Truncate`.
На Windows это не даёт нужного права усечения. Патч открывает `O_WRONLY`,
усекает до последнего целого перевода строки, сдвигает позицию `Seek` и дописывает
строки с `Sync`. Транзакция остаётся под mutex и `platform.WithLock`; тот же
замок используют prune и forget. Второй процесс роутера возможен при пересечении
запусков, поэтому межпроцессный замок обязателен.

Патч усиливает `TestMapUnique/torn-tail` длинным хвостом, добавляет `two transactions`
и `empty file`. Длинный хвост нужен, чтобы мутация без Truncate не пряталась
за более длинной новой строкой. Удаление Seek и Truncate должны краснить тесты
на всех ОС; возврат O_APPEND проверяется именно живым Windows-прогоном.

Проверка применимости патча к `1f08627` прошла. Ревью и фактическое исправление
на Windows не подтверждены. Автоматического применения в этом комплекте нет.

## Сохранённый тест задачи 1.3

`artifacts/keys_test.go.pending` — точная копия незакоммиченного теста.
SHA-256: `49022c56d34139f7265eeb3aac5a46c44deb6876aeeb640fe67065c550b944e2`.
Оригинал в исходной рабочей копии не изменялся и не добавлялся в коммит.

Тест ожидает `keyStore`, `Options.keys`, `Counters.KeysLost`, `Runtime.logf`,
`Runtime.openKeys`, `RuntimeState.MaskUnavailable` и `RuntimeState.Unavailable`.
Эти API отсутствуют в базе; запуск пакета privacy с активированным тестом
останавливается на компиляции. После реализации интерфейсов нужно проверить сами
утверждения: ключа нет в обычных файлах; рестарт читает прежний ключ; Forget
удаляет ключ; пропавший ключ не заменяется новым; отсутствие OS store/Windows
logon session закрывает запрос, именует причину и пишет её один раз.

Предварительные решения прежнего исполнителя, **не реализованный контракт**:
подменяемое хранилище ключей по home для синтетических тестов, seam открытия
ключей и логирования в Runtime, счётчик потерянных ключей; до v3 нет кэша ключей.
Пакетная переменная для тестовой подмены обсуждалась, но безопасную конструкцию
инъекции и отсутствие гонок необходимо подтвердить при реализации.

## Известные ограничения и осторожность при интеграции

- После ошибки cleanup legacy-файл с настоящими значениями может остаться до
  следующего успешного построения политики. Это видно в `LegacyErrors` и логе;
  cleanup не блокирует трафик. Уборка повторяется при ошибке, после успеха — один
  раз на Runtime. Файл, созданный позже, уберётся только при новом Runtime.
- Launchd создаёт приватный лог при Install. Если лог удалить между Install и
  bootstrap, launchd может пересоздать его 0644 до следующей установки.
- Старые журнальные результаты полного набора: timeout
  `TestCodexUsageRefreshStartsWhenASlotActivates` под нагрузкой и CIDR-падение
  `TestRestoreRunsOnlyNetworkDetectors` до исправления PRF. Это исторические
  наблюдения, не основание списывать любое новое падение на флейк.
- Реальный Windows OS store нельзя подтвердить одним cross-build. Прогон из
  SSH-сеанса ранее получил 1312: отсутствовал logon session с credential vault.
  Нужен подходящий runner/сеанс; SKIP не равен PASS.
- Публичный GitHub-контекст обезличен. История существующих кодовых коммитов и
  синтетические fixtures не переписываются; это не обезличивание всего repo.

Результаты проверки именно этой передачи — в [VERIFICATION.md](VERIFICATION.md).
