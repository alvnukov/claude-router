## Профили и назначения

Настройки сохраняются рядом с `providers.json` в `privacy-profiles.json`.
Формат version=1: enabled (общий выключатель), default (ID профиля либо пусто),
profiles (id, name, enabled, mode, rules), bindings (kind, target, profile).
`rules` — полный объект правил privacy.json, дополненный `filters`.

`mode` — `mask` по умолчанию или `detect` («Только детектировать»).
В режиме детекта исходные данные передаются модели без защиты. Он предназначен
для заведомо некритичных тестов: показывает категории и количество находок,
не создаёт псевдонимы, словари и восстановление ответа. Назначения и отдельные
переключатели фильтров действуют в обоих режимах. Неизвестный режим отклоняется.
Лаборатория позволяет проверить детектор всего профиля либо одного фильтра;
результат сохраняет исходный текст, не показывает успешный roundtrip и не
предлагает демаскирование. Счётчики детекта отделены от маскирования и от трафика.

```json
{
  "version": 1,
  "enabled": true,
  "default": "office",
  "profiles": [{
    "id": "office", "name": "Офис", "enabled": true,
    "rules": {"domains": ["example.internal"], "filters": {"phone": false}}
  }],
  "bindings": [
    {"kind": "model", "target": "cloud/model-a", "profile": "office"},
    {"kind": "pool", "target": "work/fast", "profile": "office"},
    {"kind": "provider", "target": "cloud", "profile": "office"}
  ]
}
```

Выбирается ровно один профиль: **модель → пул → провайдер → default**. Пул указан
вместе с профилем маршрутизации (`work/fast`), чтобы одинаковые имена пулов не
пересекались. Модель — фактический ключ назначения после маршрутизации, не
семейство входного запроса. Идентификаторы сравниваются точно, без glob/fuzzy.
Провайдер и модель должны описывать одну фактическую цель; UI проверка выбора
позволяет моделировать её. При failover профиль разрешается заново по фактической цели до отправки.
Прямой Anthropic имеет provider=anthropic и model=имя отправляемой модели.

Выключенный совпавший профиль означает явный bypass, без падения к менее
приоритетному профилю. Общий выключатель или отсутствие назначения также дают
bypass. Неизвестная ссылка на профиль, дубли ID/назначений, неизвестные поля,
ошибочные правила (включая выключенные профили) отклоняются. Удаление используемого
профиля в UI требует сначала снять назначения. Неверный файл не трактуется как
разрешение отправить исходный текст; интеграция должна блокировать отправку.

Профили редактируются как черновик; сохранение — отдельное действие. Импорт
privacy.json переносит его правила в черновик, сам исходный файл не меняется.
Ответ сохранения содержит снимок именно записанной версии, сформированный под
тем же lock. Все действия над черновиком, включая Undo, блокируются на время
сохранения/проверки правил. Атомарная запись mode 0600, межпроцессный lock и SHA-256 revision предотвращают
потерю правок параллельных вкладок. Windows использует ACL родительской директории.
Пределы: 32 профиля, 256 назначений, rules до 64 КиБ, файл до 256 КиБ, lock до 3 s.
Внешний редактор должен также использовать lock для исключения узкого TOCTOU;
revision ловит правки, завершённые до чтения под lock. Proxy получает снимок файла на каждом запросе; текущий обмен сохраняет прежние
правила. Кнопка «Перечитать файл» обновляет редактор.

## Фильтры

`filters` — object boolean. Отсутствующий ключ означает enabled=true, null и
неизвестные ID — ошибка. ID: ipv4, ipv6, mac, host, email, phone, secret,
dictionary, patterns, fields, sources. UI содержит переключатель, объяснение и
«Проверить отдельно» для каждого. Домены/сети редактируются простыми полями;
словарь, типизированные поля, RE2-шаблоны и исключения — JSON-редактором.

Переключатели управляют **источниками обнаружения**, а не глобальным запретом
маскировать тип. Например, выключенная email-эвристика не отключает явно заданную
запись email в словаре или typed field. Dictionary включает автоимя пользователя
и компьютера. Отключение fields не отключает распознавание password/API-key
свойств фильтром secret. Sources=withhold заменяет поддержанные вложения заглушкой;
они не восстанавливаются. При sources=pass или выключенном sources вложения
остаются видимыми. Проверки неоднозначности, типов, JSON и известного кодирования
не являются выключаемыми детекторами.

Демаскирование использует тот же Engine/Request-снимок, которым маскировали вход.
Нельзя независимо отключить восстановление уже выданного словаря. Переключение
профиля должно действовать только на новые запросы. Будущая интеграция должна
изолировать сессионные словари по профилю/ревизии: текущий P1 disk store не знает
профилей, поэтому нельзя открывать разные правила над одной директорией сессий.

## Лаборатория

Текст или Anthropic Messages JSON → маскированное содержимое → редактируемый
предполагаемый ответ → демаскирование тем же словарём. Есть синтетические примеры,
изменение маркера по явной кнопке и возврат точного ответа. Никакого вызова модели,
исполнения shell/инструментов или фоновой отправки данных.

Можно проверить весь профиль (в том числе явный bypass выключенного профиля)
либо ровно один фильтр. Изолированный тест явно включает выбранный фильтр и
отключает остальные, не изменяя профиль. Общий выключатель назначений не мешает
ручной локальной проверке. Можно тестировать текущий несохранённый черновик.

Отображаются количество вхождений по типам, размеры, время, точность обратной
проверки. Точный roundtrip **не доказывает полноту детекции**. В свободном тексте
неизвестный маркер может оставаться видимым со счётчиком unexpected; в typed tool
полях неверное имя/логин/пароль/тип вызывает отказ. Ошибка не выдаёт частичный
восстановленный результат; пользователь исправляет ответ и повторяет проверку.

Предел UI: 256 КиБ входа, 1 МиБ ответа, до 4 словарей, одна CPU-проверка одновременно.
Это ограничение лаборатории, а не размер контекста контракта P1 (JSON до 32 МиБ).
Производительность 400k токенов и 2000 RPS этим этапом не заявляется. Нет усечения.
Контекст HTTP проверяется до/после CPU-операции; прервать текущий алгоритм внутри
сканирования нельзя. Ошибка занятого лимита — 429.

Словарь держится в RAM до 5 минут после завершения маскирования. Случайный 192-bit
handle — capability, передаётся только в POST body. Таймер освобождает словарь без
последующих запросов. Clear/уход с privacy страницы освобождают раньше; при аварии
браузера гарантией остаётся TTL. Переключение внутренних вкладок оставляет текущую
проверку доступной. Очистка ссылок не гарантирует физическое зануление памяти Go/JS.
Исходный текст в редакторе остаётся до очистки или ухода со страницы.

## HTTP и наблюдение

- GET /api/ui/privacy — агрегаты лаборатории и 20 событий без содержимого;
  trafficApplied означает наличие интеграции, traffic содержит status/enabled,
  protected/bypassed/rejected/restored/active и buffered. Счётчики рабочего
  обмена отделены от лаборатории; при глобальном off запросы в них не входят.
- GET /api/ui/privacy/config — локальный редактор профилей, **включает правила и
  словари**; не является обезличенной статистикой.
- GET /api/ui/privacy/rules — явный импорт локального privacy.json; нет параметра path.
- POST /api/ui/privacy/config — revision + config, проверка active lifecycle.
- POST /api/ui/privacy/validate — исходная строка rules; строгая проверка до JSON.parse
  в UI. Повторяющиеся ключи не могут незаметно выключить фильтр.
- POST /api/ui/privacy/preview — mode, input, rules, enabled, filter (optional).
- POST /api/ui/privacy/restore — id, input. POST /clear — id, идемпотентно.

Все POST требуют JSON, строгой схемы, уникальных ключей, не более 2 МиБ envelope.
Применяется существующий Secure (локальный Host, same-origin mutation, CSP,
no-store). В логах/истории/URL/localStorage/sessionStorage нет текстов проверок,
правил черновика и словарей. Browser localStorage используется только общей темой.
UI, как и остальной пульт, доступен доверенным локальным процессам без отдельной
аутентификации; это не изоляция от вредоносного ПО той же учётной записи.

Наблюдение: mask/restore attempts (после admission), отклонённые проверки,
суммы замен по типам, число живых словарей, последние 20 времени/размеров/исходов.
Отказ admission busy не считается запуском. Данные сбрасываются при перезапуске.
GET-статистика не содержит handles, оригиналов, псевдонимов или причин с raw data.
Ошибки парсеров переводятся в фиксированные безопасные коды/сообщения.

из-под того же lock, а не последующим чтением файла.
