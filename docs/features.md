# claude-router: функциональный обзор

Назначение: безопасно переключать модели под Claude Code, видя полную картину лимитов и расхода (сейчас она неполная, см. разделы 9–11).
Для Claude Code роутер прозрачен: он выглядит как API Anthropic и сам решает, куда отправить запрос.

Состояние на 2026-09-25, коммит c330a5f: origin/main 5273818 и статистика здоровья участников пула. Ссылки `файл:строка` указывают на этот коммит, кроме разделов 3, 5, 7, 8 и 10: они обновлены вместе с несколькими подключениями Codex и типами пулов, и их ссылки указывают на код этого изменения.
Запущенный бинарь может быть собран из более старого коммита; `./router restart` пересобирает его. На дату документа так и есть: `GET 127.0.0.1:8788/api/limits` отвечает 404.

## Как устроено

- Один процесс `localrouter` (Go), `./router build` собирает его в `$ROUTER_HOME/localrouter` (`router:25`).
- Два HTTP-порта: API-прокси `ROUTER_LISTEN`=127.0.0.1:8787 (`main.go:78,195`) и UI `ROUTER_UI_LISTEN`=127.0.0.1:8788; пустое значение выключает UI (`main.go:87,191-194`).
- Фоновые задачи: каждые 2 с перечитывает `env` и `providers.json` (`main.go:182`, `settings.go:87-115`), проверяет модели пулов (`checker.go:20`), раз в час обновляет каталоги (`catalog.go:110-129`). На время входа в Codex слушает 127.0.0.1:1455 (`codex_oauth.go:22,59`).
- Состояние лежит рядом с бинарём, в `ROUTER_HOME` (по умолчанию `~/.claude/local-router`): `env`, `providers.json` (+ `providers.json.profiles/`, `providers.json.active-profile`, резервные копии `.before-*`), `models.json` (рейтинги), `history.jsonl`, `limits.json` (+ `.lock`), `router.log`, `router.pid` (`router:8-16`, `providers.go:62-70`, `health.go:57-65`, `history.go:16-24`, `limits.go:78-86`).
- Вне `ROUTER_HOME` лежат `~/.config/claude-router/codex-auth.json` (`codex_auth.go:59-62`) и `~/.claude/settings.json` с `settings.json.router-proxy-backup` (`claude_proxy.go:35-45`).
- Бинарь сам читает `env` при старте (`settings.go:46-59`). Адреса и upstream читаются только при старте (`settings.go:83-86`).

## 1. Перехват Claude Code (ANTHROPIC_BASE_URL)

- **Что делает:** по кнопке записывает адрес роутера в `env.ANTHROPIC_BASE_URL` пользовательского `settings.json` и сохраняет прежнее значение в `settings.json.router-proxy-backup` (0600, атомарно). Обратная кнопка возвращает прежнее значение или удаляет ключ, а правки, сделанные с тех пор в файле, сохраняет. Восстановление отказывается, если значение уже изменили вне роутера; любая запись отказывается, если файл поменялся во время записи (`claude_proxy.go:146-227`, проверки `:182-183,203-209`). Симлинк на `settings.json` сохраняется (`claude_proxy.go:68-72`). Второй способ: `claude-local` задаёт переменную только своему процессу `claude` и сначала запускает роутер, если тот не отвечает (`claude-local:16-22`).
- **Где настраивается:** UI `/settings`, карточка «Claude Code»: «Подключить Claude к роутеру» и «Восстановить настройки Claude». Каталог задаёт `CLAUDE_CONFIG_DIR` (`claude_proxy.go:36`), адрес берётся из `ROUTER_LISTEN`, при этом 0.0.0.0 заменяется на 127.0.0.1 (`claude_proxy.go:47-62`).
- **Код:** `claude_proxy.go:260` (`settingsClaudeProxy`), `claude_proxy.go:146` (`set`).
- **UI/API:** `POST /settings/claude-proxy`, `op=connect|restore` (`ui.go:124`).
- **Ограничения:** включается и выключается только вручную. Роутер не трогает `settings.json` ни при старте, ни при остановке, ни при падении: обработки сигналов в `main` нет (`main.go:171-198`), поэтому адрес продолжает указывать на 8787. Процесс заново поднимает launchd (`router:47-49`), а без агента связь пропадает до ручного восстановления. Что делает Claude Code, когда адрес недоступен, — не проверено. Изменение действует после перезапуска Claude Code (`claude_proxy.go:278`); по подсказке в UI, настройки проекта могут его переопределить (`ui/settings.html:186`). Журнала изменений нет: `claude_proxy.go` ничего не пишет в `router.log` (пакет `log` не импортирован, `:3-13`), хранится только последняя резервная копия, и восстановление её удаляет (`:221-225`). `claude-local` требует файла `env` с `ROUTER_LISTEN` (`claude-local:7,16,20`).

## 2. Проксирование в облако Anthropic

- **Что делает:** если маршрут запроса к `/v1/messages` — «Anthropic», обратный прокси отправляет в `ROUTER_UPSTREAM_URL` то же тело байт в байт и заголовки клиента (`Authorization`/`x-api-key`, `anthropic-*`, `User-Agent`), а ответ стримит без буферизации (`main.go:201-219,264-273`). Учётные данные роутер не добавляет и не подменяет. Все прочие пути, кроме служебных, проксируются так же, без проверки маршрута (`main.go:301-303`).
- **Что меняется в запросе:** `Host` переписывается на хост upstream (`main.go:217`). При включённом UI удаляется `Accept-Encoding`, чтобы история видела несжатое тело (`main.go:265-271`). Стандартный `httputil.ReverseProxy` убирает hop-by-hop заголовки и добавляет `X-Forwarded-For: 127.0.0.1`.
- **Где настраивается:** `ROUTER_UPSTREAM_URL`, по умолчанию `https://api.anthropic.com` (`main.go:69`), читается только при старте. Маршрут «Anthropic» задаётся в `/settings#routes`.
- **Код:** `main.go:200` (`newMainHandler`): `/v1/messages` `:230-276`, `count_tokens` `:278-295`.
- **UI/API:** 127.0.0.1:8787 `/v1/messages`, `/v1/messages/count_tokens`, `GET /healthz` → `ok` (`main.go:297-299`). Остальные пути уходят в upstream.
- **Ограничения:** маршрут «Не настроено» даёт 400 `invalid_request_error` без обращения к провайдеру (`main.go:162-167,259-261`), а у новой установки маршрутов нет вообще (`providers.go:407,512-523`). Нет соединения с upstream — ответ 502 `upstream unreachable` без повторов и без запасного пути (`main.go:202-205`). Для маршрутов, которые ведут не в Anthropic, `count_tokens` возвращает оценку `len(body)/4` (`main.go:291-294`). Запросы вне `/v1/messages` в историю не пишутся.

## 3. Локальный маршрут и подписка Codex

- **Что делает:** запросы с маршрутом «модель» или «пул» переводит из Anthropic Messages в формат OpenAI (`translate.go:152`) и отправляет либо в OpenAI-совместимый провайдер (`{base_url}/chat/completions`, `Bearer api_key`), либо в подписку Codex (`https://chatgpt.com/backend-api/codex/responses`) (`local.go:226-254`). Запросы к Codex идут без состояния на сервере (`store:false`, всегда `stream`) (`codex.go:33-98`). Ответ переводится обратно в SSE или JSON Anthropic (`local.go:395,489`). Учётные данные Anthropic провайдерам не передаются (`local.go:54-56,238-251`).
- **Несколько подключений:** каждый провайдер типа Codex — отдельная подписка со своим входом, файлом токена и каталогом моделей (`codex_stores.go:15-19`). Исходный `codex` без `auth_id` хранит учётную запись в `codex-auth.json`; остальные получают `auth_id`, их файл лежит рядом: `codex-auth-<hex имени>-<auth_id>.json` (`codex_stores.go:23-32`). Codex без `auth_id` под другим именем, повтор `auth_id` и `auth_id` у не-Codex файл провайдеров отвергает (`providers.go:138-152`). Действия `/settings/codex/*` называют подключение полем `provider`; без него или с чужим именем — 400 (`ui.go:527`).
- **Вход в Codex:** OAuth PKCE через браузер с колбэком на 127.0.0.1:1455, на вход даётся до 15 мин (`codex_oauth.go:53-91,131-196`). Другой способ — явный импорт входа Codex CLI из `$CODEX_HOME/auth.json` в выбранное подключение (`codex_auth.go:237-252`); автоматически CLI не читается. Учётная запись хранится в файле подключения (0600, атомарная запись) (`codex_auth.go:210-235`). Токен отправляется только на `https://chatgpt.com/backend-api/codex/*` (`codex_auth.go:280-283`).
- **Обновление токена:** выполняется перед запросом, если access-JWT истекает в ближайшие 30 с (`codex_auth.go:98-104,141-184`). На ответ 401 роутер один раз обновляет отвергнутый токен и один раз повторяет запрос. Если тот же токен отвергнут снова в течение минуты, сразу возвращается «сессия Codex недействительна» (`codex_auth.go:325-391`).
- **Блокировка:** загрузку, обновление и запись файла сериализует мьютекс внутри процесса (`codex_auth.go:38-49,87-105`). Обновление токена, вход и импорт вдобавок берут `flock` на `<файл>.lock` (`filelock.go:12`, `codex_auth.go:107-121,244`, `codex_oauth.go:185`); перед обновлением файл перечитывается, и токен, уже обновлённый другим процессом, берётся с диска. Файл читается один раз за жизнь процесса (`codex_auth.go:90-96`), поэтому внешняя правка видна только после перезапуска, входа, импорта или обновления токена. Работа двух процессов роутера с одним файлом — не проверено.
- **Где настраивается:** `/settings#connections`, тип провайдера OpenAI или Codex; у Codex адрес фиксирован и ключа нет (`providers.go:131-137`). Вход — `/settings#codex-subscription`, по блоку на подключение; импорт из CLI — в панели провайдера. Переменные: `ROUTER_CODEX_AUTH_FILE` (путь исходного файла; файлы остальных подключений лежат рядом), `CODEX_HOME`.
- **Код:** `local.go:57` (`handleLocal`), `local.go:226` (`tryModel`), `local.go:38` (`withoutSignedOut`), `codex_stores.go:19` (`codexStoreFor`), `codex_auth.go:87` (`credentialFor`), `codex_oauth.go:53` (`startCodexBrowserFlow`), `codex_context.go:11`.
- **UI/API:** `POST /settings/codex/login`, `POST /settings/codex/import`, `GET /settings/codex/status`, все с `provider` (`ui.go:136-138`).
- **Ограничения:** член пула, чьё подключение Codex вышло из аккаунта (нет файла или токен отвергнут), пропускается; если вышли все, клиент получает ошибку входа (`local.go:35-51,89`). Ошибка входа Codex (401) — сбой, и запрос уходит к следующему члену (`local.go:282-283,307-310`); 401 от OpenAI-совместимого провайдера — ошибка ключа, запрос не переключается. Переименовать подключение Codex нельзя: удалить, добавить и войти заново. Файл удалённого подключения остаётся на диске, удалять вручную. Для `tool_result` без парного вызова роутер ищет этот вызов в истории той же сессии; если его нет, например после вытеснения из буфера истории, запрос отклоняется (`codex_context.go:11-50`). Блоки thinking из прошлых ответов при переводе отбрасываются (`translate.go:222`).

## 4. Маршрутизация по семейству модели и effort

- **Что делает:** из запроса берёт `model` и `output_config.effort`; пустой effort считается `default` (`main.go:152-169`). Сначала ищет точное правило версии `routes[model][effort]`, затем правило семейства `family_routes[семейство][effort]`, а если нет ни того, ни другого — «Не настроено» (`providers.go:512-523`). Семейство выводится из ID регулярным выражением (`families.go:10-19`), поэтому новые версии, например `claude-opus-5-5`, наследуют правила семейства. Режимы: `disabled`, `anthropic`, `model` — один `provider/model` с фиксированным effort и без failover (`main.go:125-127`), `pool` (`main.go:128-132`). Целевой effort передаётся как `reasoning_effort` или, для Codex, `reasoning.effort` (`local.go:83-87`, `codex.go:37-41`).
- **Где настраивается:** `/settings#routes`: карточки семейств, «Версии моделей и индивидуальные настройки» (наследовать или задать явно), «Добавить другую модель Anthropic». В файле профиля — ключи `family_routes` и `routes`.
- **Код:** `providers.go:512` (`routeFor`), `main.go:114` (`forModel`), `ui.go:704` (`settingsRoute`).
- **UI/API:** `POST /settings/route` (`ui.go:126`).
- **Ограничения:** effort Claude бывает только `default|low|medium|high|xhigh|max` (`providers.go:255-261`). Ненастроенный effort не переходит на соседний, неявного отката в Anthropic или в другой пул нет. Пустой пул даёт 400 (`main.go:165-167`).

## 5. Пулы и их настройки

- **Что делает:** пул — именованный упорядоченный список `provider/model`, у каждого члена свой целевой effort (`providers.go:35-38`). Кандидаты идут в порядке пула, рейтинг порядок не меняет; модели на паузе после сбоя (cooldown) идут в конец, раньше других та, что вернётся первой (`health.go:237-248`).
- **Тип пула:** `failover` (по умолчанию; поле `type` не задано — тоже failover) — новая сессия идёт к первому здоровому члену по порядку. `balance` задаётся явно и отдаёт новую сессию подключению, у которого меньше всего сессий этого пула; подключение представляет его первый член не на паузе, при равенстве решает порядок пула (`affinity.go:24-65,112-114`). Другие значения отвергаются (`pool_settings.go:62-66`). Тип меняется на лету из формы или файла и действует на новые сессии (`main.go:139-144`). Числовое поле пула `balance` устарело: при чтении игнорируется с одной строкой в логе и больше не пишется (`pool_settings.go:31-45`). Окно по рейтингу вне пулов задаёт только глобальная `ROUTER_LOCAL_BALANCE`.
- **Failover:** если до первого полезного события истёк таймаут, оборвалось соединение или пришёл HTTP 404/408/429/5xx, запрос уходит к следующему члену пула (`local.go:154-168,304-313`). После начала ответа модель не меняется, сбой лишь снижает её рейтинг (`local.go:172-194`). При `failover`=0 делается одна попытка у первого кандидата после сортировки, выбора типа пула и привязки сессии (`local.go:89-95`); маршрут «модель» всегда без failover (`main.go:134-136`).
- **Где настраивается:** `/settings#pools`: состав (добавить, убрать, ↑↓, effort) и форма «Сессии и таймауты». В файле профиля ключи `model_pools` и `pool_settings` (`pool_settings.go:21-27`): `type`, `failover`, `first_byte_seconds` (ожидание первого полезного SSE-события `stream_start.go:22`, для обычного ответа — первого байта, 0 — без лимита), `probe_seconds`, `max_input_chars` (обрезка контекста, `trim.go:31`, `local.go:73-81`). Пул без сохранённых настроек получает значения `ROUTER_LOCAL_*` из `env` (`pool_settings.go:47-52,97-110`).
- **Код:** `main.go:137-161`, `local.go:84-200`, `health.go:226` (`pick`), `affinity.go:42` (`balanceFirst`), `pool_settings.go:54` (`apply`).
- **UI/API:** `POST /settings/pools`, `op=create|delete|add|remove|up|down|effort` (`ui.go:1069-1143`); `POST /settings/pool-settings` (`ui.go:690-716`). Под каждым членом пула — строка его здоровья из раздела 7 (`ui/settings.html:36`, данные `ui.go:581`).
- **Ограничения:** пул, на который ссылается маршрут, удалить нельзя (`ui.go:1089-1096`). Effort члена проверяется по каталогу модели (`ui.go:1145-1168`). Одна модель входит в пул не больше одного раза (`providers.go:216-220`). `balance` считает сессии только внутри своего процесса и только по привязкам в памяти; запрос без `session_id` распределением не учитывается.

## 6. Профили

- **Что делает:** профиль — именованный набор правил: `family_routes`, `routes`, `model_pools`, `pool_settings` (`profiles.go:13-18`). Провайдеры, модели и каталог общие для всех профилей. Правки маршрутов и пулов сразу сохраняются в активный профиль (`profiles.go:41-50`, `settings.go:230-264`). Переключение действует со следующего запроса и сбрасывает привязки сессий (`profiles.go:228-256`). При первом запуске текущая настройка становится профилем `default`, а прежний файл сохраняется как `.before-profiles` (`profiles.go:165-198`).
- **Где настраивается:** `/settings#profiles`: «Клонировать активный», «Создать пустой», переключение, удаление неактивного. Файлы — `providers.json.profiles/<имя>.json` и указатель `providers.json.active-profile` (`profiles.go:148`, `providers.go:280-307,341-347`). Ручная правка подхватывается за 2 с (`settings.go:103-111`, `profiles.go:293-312`).
- **Код:** `profiles.go:200` (создать), `:228` (активировать), `:258` (удалить).
- **UI/API:** `POST http://127.0.0.1:8787/api/profiles/{name}/activate` возвращает `{"active_profile":"…"}`, а на неизвестное имя — 400 (`main.go:222-228`, `profile_http.go:9-17`). Тот же путь есть на UI-порту (`ui.go:119`). Формы: `POST /settings/profiles`, `/settings/profiles/activate`, `/settings/profiles/delete` (`ui.go:120-122`).
- **Ограничения:** активный и последний профиль удалить нельзя (`profiles.go:265-270`). Автоматического переключения, например по остатку лимита, нет: активация вызывается только из UI или API (`profile_http.go:11,25`). Когда удаляют модель, ссылки на неё чистятся и в неактивных профилях (`profiles.go:89-120`).

## 7. Здоровье и рейтинг моделей

- **Что делает:** для каждой `provider/model` ведётся `modelStat` (`health.go:27-42`): score — экспоненциальное скользящее среднее (EWMA) успехов с α=0.25; TTFB — EWMA времени до первого полезного события; пауза после сбоя (cooldown) — 20 с, удваивается до 5 мин (`health.go:20-25,123-162`). Счётчики: `failovers` — сколько раз запрос ушёл с модели, `served_after` — сколько раз модель подхватила запрос после чужого сбоя (`health.go:164-170`, вызов `local.go:165`). Фоновые проверки: моделям пулов без трафика дольше `probe_seconds` уходит `ping` на 1 токен; модель из нескольких пулов проверяется по самому короткому интервалу; модели Codex не проверяются (`checker.go:20-124`).
- **Где настраивается:** `probe_seconds` в настройках пула. Файл — `models.json` (`ROUTER_MODELS_STATE`; при пустом значении состояние хранится только в памяти) (`health.go:60-68`).
- **Код:** `health.go:123` (`note`), `health.go:226` (`pick`), `checker.go:20` (`startChecker`).
- **UI/API:** одна строка на модель, общий шаблон `model-stats` (`ui/settings.html:175-177`): ответы и сбои, сбоев подряд, рейтинг (score в %), первый байт (TTFB), пауза с остатком или «доступна», «ушла дальше» (`failovers`) и «подхватила» (`served_after`), фоновые проверки успех/сбой, давность последнего успеха, последняя ошибка. Строка стоит под каждым членом пула в `/settings#pools` (`ui/settings.html:36`) и под каждой моделью в `/settings#connections` → «Каталог добавленных моделей» (`ui/settings.html:71`). Данные — копия `modelStat` под мьютексом (`health.go:299`, `snapshot`), процент и TTFB считают `ScorePct` и `TTFB` (`health.go:46-47`). Эндпоинт сброса — `POST /settings/models op=reset` (`ui.go:1551-1553`).
- **Внутри пула:** рейтинг не задаёт порядок членов, его задаёт порядок пула; пауза после сбоя по-прежнему отправляет члена в конец (`health.go:237-248`). Отмена запроса клиентом (Esc) — не сбой: рейтинг не меняется (`local.go:144,157-159,185-188`). Ошибка входа Codex (401) — сбой: она записывается в рейтинг и переводит запрос к следующему члену (`local.go:160,282-283,307-310`).
- **Ограничения:** строка — снимок на момент загрузки страницы, сама не обновляется. Кнопки сброса в шаблонах нет. Маршрут «Anthropic» в рейтинге не участвует.

## 8. Привязка сессий

- **Что делает:** если в запросе есть `metadata.user_id.session_id` (`capture.go:52-66`), первый выбранный член пула закрепляется за ключом sha256(сессия, модель, effort, активный профиль, пул) (`affinity.go:67-82`). Привязка помнит пул и подключение. Пока член здоров, следующие запросы сессии идут к нему, на то же подключение и ту же модель, какими бы ни были рейтинг и нагрузка (`affinity.go:84-127`). После сбоя привязка переходит к члену, который подхватил запрос, и обратно не возвращается (`affinity.go:129-138`, `local.go:166,191`). Отмена клиентом (Esc) привязку не трогает (`local.go:157-159,185-188`). Если у закреплённого члена сменились провайдер или effort или он пропал из пула, привязка сбрасывается (`affinity.go:100-110`).
- **Где настраивается:** отдельных настроек нет; тип пула `balance` распределяет только новые сессии, закреплённые остаются на месте.
- **Код:** `affinity.go:84` (`bindCandidates`), вызов в `local.go:91`.
- **UI/API:** своего интерфейса нет; история группирует запросы по сессиям.
- **Ограничения:** привязки живут только в памяти процесса и теряются при перезапуске: на диск пишется лишь рейтинг (`health.go:183-201`). TTL — 24 ч без активности, не больше 4096 ключей, при переполнении вытесняется самый старый (`affinity.go:94-98,115-124`). Переключение профиля сбрасывает все привязки (`profiles.go:252-254,308-310`). Запрос без `session_id` выбирает модель заново каждый раз.

## 9. Лимиты Anthropic (пассивно)

- **Что делает:** из ответов Anthropic на `/v1/messages`, прошедших через роутер, копирует только заголовки `anthropic-ratelimit-*` (не больше 64, имя до 128 байт, значение до 256 байт) и время наблюдения. Ответ без таких заголовков отмечается отдельно, ошибки без заголовков игнорируются (`limits.go:159-184,347-363`). Сам роутер к Anthropic за лимитами не обращается (`limits.go:18-24`).
- **Свежесть:** `unverified` — заголовки видели не больше 30 мин назад; `no_headers` — свежий ответ пришёл без заголовков; `unavailable` — наблюдений нет или они старше 30 мин (`limits.go:28,365-397`).
- **Где настраивается:** `ROUTER_ANTHROPIC_LIMITS_FILE`, по умолчанию `limits.json` рядом с бинарём; пустое значение — только память (`limits.go:78-86`). Запись идёт в фоне: состояние сливается с файлом под `flock` на `limits.json.lock` (ожидание до 2 с), побеждает более новое (`limits.go:130-155,292-342`).
- **Код:** `limits.go:347` (`observeResponse`, подключён в `main.go:208-210`), `limits.go:367` (`view`).
- **UI/API:** `GET http://127.0.0.1:8788/api/limits` → `{state, observed_at, age_seconds, max_age_seconds, headers}`; в `headers` только имена (`limits.go:66-74,399-405`). В UI — `/settings#anthropic-limits`.
- **Ограничения:** значения не показываются: их смысл для подписки — не проверено (`limits.go:22-24`). Без свежего трафика по маршруту «Anthropic» состояние — `unavailable`. При остановке `main` не вызывает `close()`, который дописывает отложенное сохранение (`limits.go:269-287`).

## 10. Лимиты Codex

- **Что делает:** для каждого подключения Codex отдельно показывает email, план, ID, окна лимитов (остаток в %, время сброса), дополнительные лимиты и число кредитов сброса. В сеть уходит только `GET https://chatgpt.com/backend-api/wham/usage` по кнопке «Обновить лимиты» (`codex_usage.go:16,145-180`). Открытие страницы читает кеш (`codex_usage.go:260-314`).
- **Где настраивается:** `/settings#codex-subscription`, блок на подключение; кнопка «Лимиты Codex» в полосе статуса (`ui/layout.html:82`).
- **Код:** `codex_usage.go:331` (`settingsCodexUsage`), `:351` (`usageCache`), `:260` (`get`), `:197` (`decodeCodexUsage`).
- **UI/API:** `GET /settings/codex/usage?provider=<имя>` читает кеш, `POST /settings/codex/usage` с `provider` запрашивает OpenAI (`ui.go:139-140`).
- **Ограничения:** кеш живёт только в памяти, у каждого подключения свой (ключ — имя и `auth_id`, `codex_usage.go:351-364`), привязан к аккаунту и сбрасывается при его смене (`codex_usage.go:269-272,289-293`). Лимиты показаны для всего аккаунта, а не только для запросов через роутер. Автоопроса нет. Редиректы запрещены, ответ — не больше 1 МиБ (`codex_usage.go:159,171-174`).

## 11. История запросов

- **Что делает:** каждый запрос `/v1/messages` на любом маршруте, включая отклонённые, попадает в кольцевой буфер. После завершения он дописывается строкой в `history.jsonl` (0600, в файле есть промпты). Когда строк становится больше удвоенного размера буфера, файл перезаписывается только буфером (`main.go:250-258`, `capture.go:147-162,260-283`, `history.go:74-105`). Ответ копируется в буфер до 8 МиБ и не задерживает отдачу клиенту (`main.go:21,253`, `capture.go:234-249`).
- **Поля записи** (`capture.go:19-45`; ключи JSON совпадают с именами полей Go): `ID, Seq, Start, End, Path, Model, Route` (`cloud|local|disabled`), `Session, Stream, Headers` (только `User-Agent, Anthropic-Beta, Anthropic-Version, X-App, Content-Length`, `capture.go:285-293`), `ReqBody`. Для локального маршрута ещё `OpenAIBody, TrimBefore, TrimAfter, TrimNotes, Served, Attempts[{Model,Err,Dur}]`. Результат: `Status, RespCT, RespBytes, RespTruncated, Resp{Blocks,StopReason,Usage,Model,Error,Note,Events}`.
- **Где настраивается:** `ROUTER_UI_HISTORY` — размер буфера, по умолчанию 300; `ROUTER_UI_HISTORY_FILE` — путь к файлу, пустое значение — только память (`main.go:88`, `history.go:16-24`).
- **Код:** `capture.go:260` (`finish`), `history.go:27` (`load`), `ui.go:281` (`list`), `ui.go:370` (`detail`).
- **UI/API:** `/` — список по сессиям с деталями; `GET /requests?q=&route=&model=&session=&limit=`, `GET /requests/{id}?view=structure|sent|response|raw`, `/requests/{id}/request.json|sent.json|response.txt`, `POST /requests/clear`, полоса статуса `GET /status` (`ui.go:109-116`).
- **Ограничения:** в записи нет профиля, пула и effort (effort остаётся только внутри `ReqBody`). Расход токенов есть лишь в `Resp.Usage` отдельного запроса; сводки по сессиям и моделям нет.

## 13. Каталог моделей

- **Что делает:** каталог хранится в `providers.json`, а не в `models.json`, где лежат рейтинги (раздел 7). В нём `providers` (имя, тип, `base_url`, `api_key`), `models` (`provider/model`) и `catalog` (ID моделей Anthropic, каталоги провайдеров с уровнями effort, `codex_seen`) (`providers.go:19-60`, `catalog.go:20-37`). Каталог обновляется при старте и раз в час: ID Anthropic разбираются со страницы platform.claude.com/docs/en/models/overview, у провайдеров запрашивается `GET {base_url}/models`, у Codex берётся каталог аккаунта с `supported_reasoning_levels` (`catalog.go:84-191`, `ui.go:1214-1303`). Если обновление не удалось, остаётся прежний каталог и появляется заметка (`catalog.go:150-166`). Новая версия Codex попадает в каталог и в те пулы, где уже есть более ранняя модель того же варианта; effort она наследует от неё, если каталог его подтверждает. Модель, удалённая вручную, обратно не добавляется (`catalog.go:196-304`).
- **Как добавить модель:** `/settings#connections` → «Модели и подключение» у провайдера → выбрать модель из списка, который отдаёт провайдер (`POST /settings/models op=add`, `ui.go:1450-1455`), затем включить её в пул или назначить напрямую. Модель Anthropic для отдельного правила добавляется через «Добавить другую модель Anthropic» в `/settings#routes` (`ui/settings.html:21`). Вручную — правкой `providers.json`.
- **Код:** `catalog.go:133` (`refreshModels`), `catalog.go:196` (`inheritCodexModels`), `ui.go:793` (`settingsProviders`), `ui.go:1440` (`settingsModels`).
- **UI/API:** `POST /settings/refresh-models`, `GET /settings/provider?name=`, `POST /settings/providers op=add|update|remove`, `POST /settings/models op=add|remove` (`ui.go:127-136`).
- **Ограничения:** список ID Anthropic зависит от HTML-разметки страницы документации; при пустом каталоге используется встроенный список (`providers.go:46`, `ui.go:570-573`). Удаление модели или провайдера выключает прямые маршруты на неё и убирает её из пулов всех профилей (`ui.go:1456-1473,876-907`, `profiles.go:89-120`). При добавлении проверяется только формат ID и наличие провайдера (`providers.go:150-169`).

## 14. Деплой и надзор за процессом (launchd)

- **Что делает:** `./router install` собирает бинарь, пишет LaunchAgent `com.claude-local-router` (RunAtLoad, KeepAlive, ThrottleInterval 10 с, вывод в `router.log`) и загружает его (`router:36-66`). Когда агент установлен, `start`, `stop` и `restart` работают через `launchctl` (`router:83-117`). `restart` — это сборка, `kickstart -k` и ожидание `/healthz` до 5 с (`router:29-34,110-114`). Без агента роутер запускается фоновым процессом с `router.pid` (`router:90-94`). `claude-local` запускает роутер через `router start`, если `/healthz` не отвечает (`claude-local:16-18`).
- **Где настраивается:** `ROUTER_HOME`, файл `env`, из которого скрипт читает `ROUTER_LISTEN` (`router:14,21-22`).
- **Код:** `router`, `claude-local`, `main.go:171` (`main`).
- **UI/API:** `GET /healthz` на 8787; `./router status|logs`.
- **Ограничения:** перезапуск обрывает запросы в работе, а пока процесс поднимается, порт закрыт: мягкой остановки (graceful shutdown) нет (`main.go:195`, сигналы не обрабатываются). `stop` при установленном агенте выгружает его до следующего входа в систему или `start` (`router:97-101`). Надзор (подъём после падения) есть только с LaunchAgent, то есть на macOS (`router:17-19,47-49`); без агента упавший процесс поднимет разве что следующий запуск `claude-local` (`router:90-94`, `claude-local:16-18`). При остановке `settings.json` не откатывается (раздел 1).

## В работе (не в main)

Этих возможностей в origin/main нет, пользоваться ими нельзя.

- **Не доступно.** Деплой без обрыва (blue/green через Caddy) — в работе. До слияния действует раздел 14: перезапуск обрывает запросы.
- Несколько подключений Codex и типы пулов `failover`/`balance` описаны в разделах 3, 5, 7, 8 и 10.

## Как дополнять

- PR, который меняет поведение, в том же PR правит соответствующий раздел: текст, ссылки `файл:строка`, строку «Состояние на».
- Новая возможность — новый раздел с теми же полями: «Что делает», «Где настраивается», «Код», «UI/API», «Ограничения».
- Что не видно из кода, помечать «не проверено» и не додумывать.
- Когда ветка из «В работе» сливается, её строку заменяет раздел возможности.
