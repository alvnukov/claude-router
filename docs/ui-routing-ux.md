# Настройка маршрутов и наблюдаемость

## Сделано в UI worktree

- Простое назначение показывается строкой «семейство → пул / модель».
  Отдельные уровни раскрываются кнопкой «Настроить по effort»; исключения
  показываются сразу. Несохранённое сопоставление можно отменить.
- У пула есть явная кнопка клонирования. Копируются порядок моделей,
  настройки поведения, основное правило effort и индивидуальные соответствия.
  Изменения копии не затрагивают исходный пул и другие профили.
- У участника пула три варианта основного правила: значение по умолчанию
  модели, фиксированный effort, effort входящего запроса.
- Индивидуальные соответствия раскрываются внутри участника. Приоритет:
  соответствие для effort пула → основное правило участника. Пустое значение
  означает «по умолчанию модели», отсутствие соответствия — основное правило.
  Сохранение effort не преобразует max в xhigh: необходимый уровень должна
  поддерживать принимающая модель. Фиксированные значения проверяются по
  доступному каталогу; старые неподтверждённые значения видны явно.
- Настроенные исключения видны короткой строкой даже при закрытом редакторе.
- Состояние паузы участника пула не названо «Доступна»: отсутствие паузы после
  ошибки само по себе не подтверждает авторизацию или наличие лимита.
- В деталях запроса показаны входная модель/effort и последняя отправка.
  Значения извлекаются из записанных тел запроса, а не из текущего конфига.
  Отсутствие записи отличается от отправки без effort.
- Элементы пула привязаны к идентификаторам моделей: перестановка не переносит
  состояние формы на соседнюю модель. Проверено сохранение выбранных значений
  при фоновом обновлении состояния.

- В профиле доступен пул по умолчанию для моделей без правил версии/семейства.
  Пустой выбор отклоняет такие запросы. Явное отключение и незаданные уровни
  модели с существующими правилами не обходятся через пул по умолчанию.
- В истории есть фильтр «Не распознано»: нестандартные пути, ошибки разбора,
  отсутствующие маршруты и применение пула по умолчанию. Видны метод, путь,
  исходная модель, причина и сырые тела. Успешная пересылка не считается ошибкой.
  Неполный захват обозначен; заголовки авторизации и параметры адреса не записываются.

## Следующие приоритеты — ещё не реализовано

1. **Проверка маршрута до отправки.** Выбрать семейство/версию и effort;
   увидеть применённое правило, пул, порядок кандидатов, effort каждого,
   недоступные модели и несовместимые уровни. Отдельно объяснять зависимость
   от привязки уже существующей сессии. Проверка не отправляет платный запрос.
2. **Причина выбора в истории.** Записывать профиль, версию настроек, пул и
   effort каждой попытки в момент запроса; показывать причины пропуска и
   перехода на резервную модель. Сейчас история содержит попытки и последнюю
   отправку, но полного снимка решения нет. Не восстанавливать прошлый
   маршрут по сегодняшним настройкам.
3. **Предпросмотр изменения и откат.** Перед сохранением показывать затронутые
   маршруты; хранить версии настроек и давать отменить последнее сохранение.
   Добавить предупреждение о несохранённой форме при уходе и смене профиля.
4. **Сводка проблем, требующих действия.** Пустые пулы, ненастроенные уровни,
   устаревший каталог, истёкшая авторизация, исчерпанный лимит. Каждая проблема
   ведёт к конкретной настройке или запросу; неизвестное состояние не считается
   ни исправным, ни аварийным.

Первым полезнее реализовать проверку маршрута: она сразу объяснит сочетание
правил семейства, версии модели, пула и индивидуального effort без пробного
запроса и чтения JSON.
