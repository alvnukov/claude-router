# Private Gitea regression workflow

`regression.yml` is a **manual-only, fail-closed specification** for a private repository. Its presence in a branch does not mean the runner, offline image, staging, isolation or tests have been provisioned or verified. Do not publish or enable the workflow until the external pre-listener isolation gate and a separate one-run authorization have succeeded. A queued job with no registered label is **blocked**, not a passing check.

The only trigger is a trusted `workflow_dispatch` on protected `main`. There is no pull-request, fork, schedule or push trigger. Adding `push` on `main` requires a separate change after the first isolated manual run, a deliberately failing red-control run and a new authorization; there is no automatic enablement date or skip-as-pass branch. The job has one step: invoke the entrypoint supplied in an approved, digest-pinned container image. The workflow has no checkout, dependency download, tool installation, socket mount or host action. Independently verify that no repository token or secret enters the product container or any child: `permissions: {}` alone does not prove that Gitea withholds a token.

The external control plane owns the private repository, exact source and test-only integration commit verification, staging, image and dependency provenance, runner registration and proof. It must map the **sole** label `router-wsl-test` to a digest-pinned Docker image (never a host executor), keep the daemon socket and credentials outside the job and supply read-only `/workspace/source`, `/run/router-ci/proof.json` plus separate writable `/workspace/output`. The image-owned `/usr/local/bin/router-ci-entrypoint` must reject an absent or obsolete proof, verify a signed **per-run v2** proof bound to the actual container/image, fresh preflight, source tree, event commit, unique nonce and short expiry, then invoke the sole `bash internal/regression/run.sh`; the event SHA from the workflow is only a comparison value, not authority. The entrypoint also runs the CI-only report validator after a successful runner exit and returns nonzero on any missing or invalid report. If any of these interfaces is absent, the job must fail; the workflow source is **not** a security boundary.

Before starting the listener, an independent synthetic parent/child/grandchild preflight must prove the backend has no network except internal loopback, is nonroot with read-only root/source/deps and fresh writable scratch, has no host home, Windows drives, daemon socket or credentials, and cannot escape via actions/hooks. For **each** run, a trusted launcher must create and inspect the actual container, repeat the preflight in that same container/namespace, then permit its first workflow shell; after start it must check descendants. If the installed runner lacks this pre-exec seam, the listener stays off until a separately approved isolated executor provides it. The effective config, image and mounts must be bound to the per-run proof. A signature by itself does not prove runtime isolation. Support for network `none` and these namespaces remains unverified; do not infer it from YAML or environment markers.

The single test entrypoint owns builds, Go/UI/privacy tests and the sanitized machine-readable report. Its initial guard returns 78 before subprocesses and does not create `run.json`; that is **blocked**, not pass. A successful Linux report must have all mandatory gate IDs passing, including distinct privacy lab, P1 A/B, explicit exception and negative-control sensitivity evidence. The validator rejects missing, malformed or incomplete reports, wrong SHA, missing named tests/negative controls, missing `steps-evidence.json` and any blocked/not-run/failing mandatory gate. The step evidence links exact commands, exit codes and private-log digests to the same revision, but remains runner-produced provenance, not independent proof of process execution. Privacy test revision and mutation sensitivity still need independent Stage B review and negative controls; a self-declared pass or signed proof alone is insufficient. Raw `go-test.jsonl` can contain synthetic canaries on failure and stays in private scratch; only allowlisted summary data may be exported by the management plane after separate sanitization. No artifacts are uploaded from this workflow.

A Linux container result does not prove native Windows, native macOS, live deployment or end-to-end proxy privacy. Those are separate acceptance results on the exact integrated revision. The original baseline for this test-only integration is `45aae67f51b64dc744c1b54a663a308a2632c659`; the event/integration SHA must be independently approved and must match the staged source and report. The existing GitHub workflows are independent.
