# Фильтр privacy, этап P1

Изолированный пакет маскирования/демаскирования Anthropic Messages и локальная
команда предварительного просмотра. Актуальная [спецификация](SPEC.md) и
[результаты проверок / продолжение](HANDOFF.md) — рядом. Подключён к серверу и UI в ветке задачи; см.
[контракт трафика](../../docs/privacy-traffic.md). Фильтр
не добавляет исполнителя команд, локальную LLM или NER-модель.

## Правила из файла

`LoadRules(path)` / `ParseRules(data)` проверяют конфигурацию, `Open` создаёт
снимок правил. Изменение файла применяется созданием нового Engine; чтения и
компиляции правил на каждом запросе нет. Криптография, парсеры и проверка
целостности остаются кодом. Исполняемых скриптов в правилах нет.

```json
{
  "domains": ["office.example"],
  "networks": ["192.0.2.0/24"],
  "entries": [
    {"kind": "org", "forms": ["Фирма", "Фирмы"]},
    {"kind": "host", "forms": ["border1"]},
    {"kind": "login", "forms": ["AdminUser"]}
  ],
  "patterns": [
    {"name": "account-label", "kind": "login", "regex": "(?i)login=([a-z][a-z0-9_-]+)", "group": 1}
  ],
  "fields": [
    {"path": "messages[*].content[*].input.username", "kind": "login"},
    {"path": "content[*].input.username", "kind": "login"},
    {"path": "messages[*].content[*].input.server", "kind": "host"},
    {"path": "content[*].input.server", "kind": "host"}
  ],
  "sources": "withhold",
  "retain_days": 30
}
```

`patterns` задаёт контекстный шаблон и номер чувствительной группы; метка и
окружающий синтаксис сохраняются. `fields` задаёт тип **целой строки** по пути,
включая `[*]` для массива. Пути истории `messages[*].content[*]`, JSON-ответа `content[*]` и SSE приводятся к общей адресации, поэтому достаточно одного правила. Имена полей
паролей и ключей из `detection.secret_keywords` распознаются автоматически;
короткий пароль в таком JSON-поле тоже маскируется. Числовой чувствительный
аргумент отклоняется: фильтр не меняет его тип молча.

`detection` переопределяет отдельные поля из [defaults.json](defaults.json):
шаблоны сетевых адресов, email, телефонов, секретов, список ключевых слов и
окончаний для проверки коллизий. `allow` разрешает значения, `allow_paths` —
пути. Эти исключения и `sources: pass` означают явное разрешение раскрытия.
Файл политики должен быть доверенным.

Email автоматически маскируется для доменов организации; прочие email можно
задать словарём или шаблоном. Одиночные имена оборудования и персон требуют
инвентаря/словаря либо правил: отрицательный результат regex не доказывает
отсутствие чувствительных данных. `forms` — распознаваемые написания; пакет
не выводит автоматически, что разные ФИО, сокращения и логины принадлежат
одному человеку. Основа `*` сохраняет суффикс; для неоднозначных сущностей
нужны явно заданные формы и контекст. Равные строки разных типов не сливаются.

## Контракт

1. `Open(routerHome, rules, options)` создаёт Engine. Машинные имя и логин
   добавляются автоматически; `Options` позволяет подставить их в тестах.
2. `Mask(body)` возвращает тело и Request; при ошибке оба результата nil.
3. `UnmaskJSON(request, reply)` или `NewStreamUnmasker(request, writer)`
   восстанавливают ответ только по этому снимку. После ответа нужен `Close`.
4. `Forget`, `ForgetAll`, `Prune` управляют словарями. Живой Request сохраняет
   снимок даже после Forget; Close освобождает ссылки на секреты.

Повторное значение получает стабильный псевдоним в своей сессии. Явный `entries[].pseudonym` нельзя повторно выдавать другой сущности или другой сессии; такой конфликт отклоняется. Словари имён
хранятся в `ROUTER_HOME/privacy/sessions/<id>.jsonl` (0600, каталог 0700).
Ключ сессии случаен, запись завершается до выпуска результата. Секреты доступны
для восстановления только в текущем Request. На диск попадают лишь их HMAC-
отпечатки, позволяющие узнавать некоторые кодированные представления в следующих
ходах. Они не позволяют восстановить секрет по старому плейсхолдеру.

Поддержаны base64 (standard/URL, с padding и без), hex, percent encoding, до
трёх вложений. Чувствительный кодированный фрагмент заменяется целиком и может
быть точно восстановлен в текущем ответе. Это конечный набор преобразований,
а не защита от произвольной программы, дробления секрета и побочных каналов.

В явно типизированном поле инструмента требуется целый точный псевдоним ожидаемого вида. В остальных аргументах изменённый регистр известного псевдонима, чужой или
устаревший плейсхолдер, его кодированное представление, несовместимый явно
заданный тип и ранее не показанный замаскированный адрес дают `RejectError`.
Диагностика предлагает повторить точное значение без раскрытия оригинала.
Опечатки в произвольном незнакомом слове распознать надёжно нельзя. Фильтр
не исправляет shell, URL, кавычки и скобки за моделью и не проверяет допустимость
самого действия. Интеграция возвращает клиенту ошибку с предложением повторить точный псевдоним;
доставку этого сообщения модели обеспечивает клиент.

Текст SSE обрабатывается с удержанием незавершённого слова/адреса/псевдонима.
Аргументы `input_json_delta` собираются до завершения блока, проверяются как
JSON и выпускаются целиком. Некорректный JSON не исправляется. Ошибка позднего
блока не отменяет уже выпущенные ранние блоки; атомарность всего ответа не
обещается. Thinking/signature и служебные поля протокола не переписываются.
Дубликаты JSON-ключей и неизвестные типы контентных блоков отклоняются.

Лимиты: тело JSON 32 MiB, вложенность 256, SSE-кадр и собираемый блок 16 MiB,
кодируемый токен 64 KiB. Превышение обрабатываемого лимита даёт отказ, не
passthrough. Словари слов занимают около 6.4 MiB общей памяти процесса (Bloom);
память тела, разбора и снимков зависит от контекста. Кэш результатов анализа и
нагрузочные гарантии пока не реализованы.

## Локальная проверка

```sh
go run . privacy mask -rules testdata/privacy/rules.json testdata/privacy/corpus/network/core-sw1.cfg
go test ./internal/privacy/...
go test -race ./internal/privacy/...
go test ./internal/privacy -run '^$' -bench BenchmarkMaskRepeatedContext -benchmem
```

CLI пишет обезличенный текст в stdout, только счётчики в stderr. Не создаёт
словарей, не удаляет старые сессии, не отправляет данные в сеть. Если файл правил
не указан, ищет `privacy.json` в `ROUTER_HOME`; при его отсутствии явно сообщает,
что правила организации не заданы. Образцы корпуса синтетические.

Тесты включают корпус, 10 000 сгенерированных пар логин/пароль, 100 000 выдач
псевдонимов, произвольное дробление SSE, повреждение хранилища, параллельные
Engine, забывание живой сессии, вложенные кодировки и большой повторяющийся
контекст. Объём тестового контекста измеряется в байтах, а не выдаётся за точное
число токенов конкретного токенизатора. Ограничения и оставшиеся угрозы:
[THREAT_MODEL.md](THREAT_MODEL.md). Источники слов и лицензии:
[words/README.md](words/README.md).


### Профили и лаборатория в новом UI

Откройте «Конфиденциальность» (`/privacy`). Здесь можно создать профиль, выбрать
фильтры, редактировать домены/сети и JSON правил, проверить весь профиль или один
детектор и задать назначения на модели, пулы или провайдеры. Записи сохраняются
в `privacy-profiles.json` рядом с `providers.json`, отдельно от правил старого CLI.
Proxy использует назначения при включённом общем режиме; ответы целиком
буферизуются до проверки. [Контракт и ограничения](../../docs/privacy-ui.md).

Низкоуровневый SSE API выше допускает частичную выдачу. Runtime/Exchange, который
использует сервер, добавляет атомарную проверку всего ответа и строгие ограничения
непрозрачных полей. Настройка правил не гарантирует обнаружение всех персон без
словаря. Assignment-пароли распознаются после пробела и при любой ненулевой длине.
