## Interface и владение состоянием

`LoadRules`/`ParseRules` → `Open` → `Mask` → `UnmaskJSON` или
`NewStreamUnmasker` → `Request.Close`.

- Engine хранит снимок правил и доступ к словарям. Независимые Engine используют
  общий файловый lock и мьютекс внутри процесса.
- Mask при обнаруженном отказе возвращает `(nil, nil, error)`. Нельзя отправлять
  исходное тело как fallback. Это обязанность будущего вызывающего кода.
- Request принадлежит породившему Engine. Он содержит ключевой mapper,
  обратный индекс, точное написание и секреты текущего запроса. Close идемпотентен,
  снимает lease и освобождает ссылки на таблицы. Повторное восстановление закрытым
  Request запрещено. Стирание всех копий строк из Go heap не гарантируется.
- Stats содержит только количества по типам и Scope, без исходных значений.
- `Forget(session)`, `ForgetAll`, `Prune(now)` изменяют локальные словари.
  Уже открытый Request продолжает работать со своим снимком после Forget.
- API не является доказательством авторизации сессии: `metadata.user_id.session_id`
  валидируется синтаксически, но происхождение ID должен подтвердить интегратор.

## Классификация и правила

1. Ключи словаря различают **kind + точное исходное написание**. Case folding
   используется для поиска форм и проверки коллизий, а не для потери исходных
   байтов. Совпадение текста разных типов не создаёт общую идентичность.
2. Словарь `entries`, контекстные `patterns`, типизированные `fields`, сети,
   домены и исключения загружаются из JSON. Детекторы можно переопределить через
   `detection`; базовые данные находятся в `defaults.json`.
3. `fields` классифицирует целую строку. Пути history/JSON response/SSE
   нормализуются к `content[index].input...`; правило для history применимо
   к ответу. Индекс сообщения не является ограничением роли поля.
4. Ключевые слова полей паролей/ключей дают KindSecret. Шаблоны `${...}`,
   `{{...}}`, `<...>` и строки звёздочек не считаются настоящим секретом при
   маскировании. В типизированном ответе инструменту всё равно нужна точная
   доступная ссылка, либо явно разрешённое исключение.
5. `allow` действует симметрично. Если выданный псевдоним совпал с разрешённым
   значением, результат отклоняется; криптографическая перестановка не меняется
   обходом отдельных точек, который сломал бы сохранение префиксов.
6. `forms` не означает автоматическое семантическое связывание разных ФИО,
   транслитераций, email и логинов. Повторения одной формы стабильны; основы с
   `*` сохраняют окончания. Полноценный граф сущностей — дальнейшая работа.
7. При совпадающих span действуют длина и порядок согласно `resolve.go`.
   Контекст полей нужен там, где голый текст неоднозначен. Это не вероятностный
   семантический анализатор и не распознавание всех персон без словаря.

## Преобразования и обратимость

- IPv4/IPv6, CIDR, MAC: Crypto-PAn и отдельные domain-preserving преобразования,
  приватные классы и публичные сети из правил. Link-local EUI-64 связан с MAC.
- Формат MAC сохраняется; для адресов действует каноникализация `netip`.
  CIDR сохраняет выбранное старым дизайном правило обмена network/host-zero.
  Оно математически обратимо, но в исключительном случае адрес с CIDR может
  не соответствовать отдельно преобразованному голому адресу. Нельзя выдавать
  это за доказательство корректности операций над сетями.
- Имена/хосты/email/логины/телефоны: сессионная таблица. Кандидаты проверяются
  против выданных значений, правил и встроенных словарей. Явный псевдоним занят
  одной парой kind/real в одной сессии; повторная выдача другой форме/сессии
  отклоняется. Повторный Open той же корректной конфигурации разрешён.
- Секрет: `<secret:family:8hex>`, HMAC от значения и ключа сессии. Коллизия
  короткого идентификатора даёт отказ. Реальное значение существует только
  в Request; старый плейсхолдер не восстанавливается в следующем запросе.
- HMAC-отпечатки известных секретов хранятся в сессии без plaintext. Фильтр
  проверяет известные целые токены в прямом и декодированном виде, в том числе
  контейнер `result=[...]` и присваивание `token=...`. Поддержаны base64, hex,
  percent encoding, до трёх вложений. Кодированный чувствительный фрагмент
  целиком становится секретным плейсхолдером. Разбиение на поля/фрагменты,
  произвольное шифрование, binary/compressed payload и все возможные контейнеры
  не покрыты этим конечным распознавателем.
- JSON правится по исходным диапазонам. Нет прохода через `map[string]any`
  для перезаписи тела. Порядок, пробелы и числа вне span сохраняются. Точная
  исходная запись span сохраняется на время Request. Неоднозначная запись
  одного псевдонима отвергается. Для чужого псевдонима восстанавливается реальное
  значение, а не прежний псевдоним чужой сессии.
- Демаскирование — один проход: вставленный оригинал не анализируется повторно
  как псевдоним. Это предотвращает каскадную подмену.

## Поверхности JSON и SSE

Обрабатываются system, content, messages[].content, рекурсивные строки/ключи
`tool_use.input`, `tool_result.content`, описания инструментов, schema
`description/title/enum/default/const/examples`. Числовые значения не превращаются
в строки; чувствительное числовое поле даёт отказ. Идентификаторы протокола,
metadata, signatures и thinking не переписываются. Совпадение словаря в thinking
отклоняется, а отсутствие совпадения не подтверждает безопасное происхождение.

Неизвестные content types, дубликаты ключей (включая получившиеся после замены),
некорректный JSON, повреждение хранилища и превышение лимита дают отказ.
Изображения/документы withhold по умолчанию; pass — явное раскрытие по политике.

В текстовом SSE удерживается незавершённый хвост. В инструментальном SSE
весь `partial_json` накапливается до завершения блока, затем проверяется и
восстанавливается; Unicode-escape распознаётся через JSON parser. Неверные
кавычки, скобки, слеши не исправляются. В нескольких блоках атомарность действует
на блок, не на весь ответ. SSE с несколькими строками `data:` в одном событии
пока отклоняется; поддержан обычный однострочный формат Anthropic с пустым
`tool_use.input` в начальном событии. Непустой начальный input отклоняется, чтобы
не выпустить аргументы до проверки целого блока.

В типизированном аргументе нужна точная ссылка ожидаемого типа. В прочих
аргументах известные изменённые/чужие псевдонимы, неподтверждённые сетевые адреса
и кодированные ссылки дают correction. Полностью неизвестную опечатку обычного
слова от нового слова надёжно отличить нельзя. Ошибка выбора другого **уже
известного** сервера тоже не выводится из одной строки; фильтр не читает намерение.

## Хранилище и пределы

JSONL: сначала `{kind:"key",key:<32 bytes hex>}`, затем записи kind/real/pseudo/at
или `{kind:"secret_fingerprint",fingerprint:<HMAC-SHA256 hex>}`. Оборванный
последний record отбрасывается; ошибочный полный record или дубликат отвергается.
Запись синхронизируется до выдачи результата. Ключ и словарь содержат чувствительные
данные; 0600/0700 не изолируют процессы того же пользователя. Lease для Prune
учитывает живые Request внутри процесса; межпроцессные живые ответы не учитываются.

Нет обещания совместимости промежуточных экспериментальных словарей до этого
контракта. Реального развёртывания в этой работе не было. Словари с прежним
приведением real к lower-case нельзя считать доказанно безопасными для логинов.

Лимиты: JSON 32 MiB/256 уровней, SSE 16 MiB, анализируемый токен 64 KiB.
Память Bloom около 6.4 MiB на процесс плюс исходный текст, дерево и Request.
Производительность фиксируется измерениями, 2000 RPS не достигнуты и не являются
критерием данного этапа. До оптимизаций нет кэша классификации повторяющихся
контекстов; отсутствие кэша исключает его межсессионное смешение.
